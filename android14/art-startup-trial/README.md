# Android 14 ART startup and boot artifact check on SM-T700

Trial 28 runs the installed ARM32 `art_boot` service and `odrefresh --check` on Linux 6.12.118. The experiment uses the installed 31 APEX packages, the four verified classpath exports and a fresh writable tmpfs at /data. Internal MMC is read-only during the diagnostic kernel boot. [Previous classpath trial](../sdk-classpath-trial/README.md)

## Reproducing the diagnostic

1. Use the trial 27 boot inputs and its SELinux entry probe as the base. Reconstruct the previous `classpath-entry.h` as documented in that trial, copy it to `art-entry.h` and apply [art-entry.patch](art-entry.patch) there with `patch -p1`. Use this header as the SELinux entry probe. Retain the read-only MMC guard and rebuild any objects that were produced from a different source overlay, including Binder.
2. Put [klimt-art.rc](klimt-art.rc) in the embedded ramdisk as `/klimt-property.rc`. Keep the first-stage init copy into tmpfs. Use a fresh matching 16-digit hexadecimal run ID in the ramdisk, bootconfig and decompressor records. The hardware command line selects `androidboot.init_rc=/dev/klimt-property.rc`, `androidboot.klimt_art=1` and `g_serial.iSerialNumber=SMT700-ART`.
3. Run the previous APEX and SDK/classpath steps, then start the installed `logd` and run `art_boot` from the ART APEX's own init definition. Before `art_boot` both feature flags must be unset. After it exits, both `dalvik.vm.features.embedded_profile` and `dalvik.vm.features.art_managed_file_stats` must read true.
4. Run the fixed one-shot `odrefresh --check` command. The installed userdebug policy provides the transition from `su` to `odrefresh`. The short launcher uses the stock permissive `su` domain only for that transition. The kernel observes the actual ART executables running in enforcing `art_boot` and `odrefresh` domains. The shell collector reports the boot-image decision and selected messages from logd. The kernel checks that the fresh RAM cache-info path stays absent. The artifact check can clean invalid files within temporary /data. This drill does not invoke `--compile` or launch odsign.
5. Run [verify-art-log.py](verify-art-log.py) with the run ID on the hardware USB stream and retained console. The negative ARM QEMU control selects `androidboot.klimt_art=0` with the same image. It verifies the ART flags, bypasses odrefresh and returns to recovery. Pass `--negative` to verify it.

The installed product sets `ro.dalvik.vm.enable_uffd_gc=true`. Trial 28's flashed kernel has `CONFIG_USERFAULTFD` disabled. Odrefresh identifies the mismatch and returns 79, the Android 14 `kCompilationRequired` status, without accepting the /system boot images. This status also covers cases where the cache metadata needs to be generated. The logs and kernel configuration establish the observed boot-image rejection separately from the empty RAM cache.

The follow-up uses [art-uffd.config](art-uffd.config) for the one functional kernel configuration change. Use a fresh run ID and `g_serial.iSerialNumber=SMT700-ART-UFFD` on the tablet. Pass `--expect-uffd` for the positive verification. The verifier requires both ARM boot and system_server artifacts to be accepted and the userfaultfd mismatch warning to be absent. The empty temporary cache can still produce exit 79.
