# Android 14 DRM compositor on ARM VKMS

This trial runs the installed Android 14 framework with virtual KMS, ARM SwiftShader, DRM HWC and a matching allocator and mapper. It operates on a private copy of the QEMU SYSTEM fixture and leaves the physical tablet on its existing Android filesystem.

1. Enable `CONFIG_DRM_VKMS=y` and `CONFIG_DMABUF_HEAPS=y` with `CONFIG_DMABUF_HEAPS_SYSTEM=y` in the ARM virtual kernel. Use the existing [framework trial](../framework-display-trial/README.md).
2. Build `vulkan.pastel`, `hwcomposer.drm_minigbm`, `gralloc.minigbm`, `android.hardware.graphics.allocator@4.0-service.minigbm`, and `android.hardware.graphics.mapper@4.0-impl.minigbm` from the SM-T700 Android tree. Install their ARM artifacts and the missing `libminigbm_gralloc.so`, `libdrm.so`, and `libdmabufheap.so` in the copy's vendor paths. Keep the existing HWC 2.1 service. Use the stock allocator service basename and executable label, and advertise HIDL 4.0 allocator and mapper in the copied vendor VINTF manifest.
3. Select `ro.hardware.egl=angle`, `ro.hardware.vulkan=pastel`, `ro.hardware.hwcomposer=drm_minigbm`, and `ro.hardware.gralloc=minigbm`. Label `/dev/dri(/.*)?` with the existing `gpu_device` type and use `same_process_hal_file` for the new Vulkan driver, mapper, gralloc, and shared graphics dependencies. For the isolated legacy single-filesystem fixture, hard-link the labeled vendor `vulkan.pastel.so` at `/system/lib/vulkan.pastel.so` so the module name resolves from the legacy namespace. This hard link is fixture-specific.
4. Compile [the Vulkan probe](vulkan-probe.c) for ARM with `armv7a-linux-androideabi34-clang -O2 -Wall -Wextra -Werror vulkan-probe.c -ldl -llog -lvulkan -o klimt-vulkan-probe`. Install it at `/system/bin/klimt-vulkan-probe` in the fixture with the stock shell executable context. Apply [the diagnostic RC patch](klimt-vkms.patch) over trial 30's RC, then rebuild the private virtual ramdisk with a fresh run ID.

The initial ANGLE attempt found zero Vulkan physical devices. In the final comparison the standalone probe loaded the driver by name, created an instance and reported SwiftShader Device (LLVM 16.0.0). ARM QEMU recorded the hardware service manager, minigbm allocator and DRM composer running. SurfaceFlinger remained alive and was listed by Binder at uptime 114.412 s, under the same enforcing policy. The session returned to recovery at 121.174 s. Android Home, a composed frame and the device's internal display remain separate acceptance checks.

## Native Android screen capture

[The frame patch](klimt-vkms-frame.patch) starts the installed boot animation from SurfaceFlinger and invokes the stock `screencap` through the Android shell. Compile [the frame reader](frame-probe.c) the same way as the Vulkan probe with `-llog`, install it as `/system/bin/klimt-frame-probe` with the shell executable context, and preserve the frame as temporary RAM data.

SwiftShader shader compilation required `execmem` for bootanim and surfaceflinger in this private emulator fixture. The comparison against the original policy found exactly those two additional self permissions and no changes to permissive domains. SELinux remained enforcing. Use this fixture-specific policy only to reproduce the software renderer trial. The physical tablet continued using its original policy. The virtual kernel guard was widened to 175 seconds and first-stage fallback to 195 seconds for ARM emulation.

Stock Android `screencap` completed and the frame reader exited with status 0. At uptime 143.552 s the raw RGBA capture measured 1024×768 with 344 pixels whose RGB value was nonzero. The boot returned to recovery at 182.304 s. Launcher and the SM-T700 panel still require verification.

## Real Android display services from a removable system, trial 46

An SM-T700 physically booted Linux 6.12.118 with the calibrated 2-nit panel enabled and an isolated ARM Android 14 system from microSD. The verified root was read-only ext4 on loop0. Android's writable data and data mirrors were in RAM. Internal SYSTEM was independently checked read-only before the switch to the removable root.

[The Exynos minigbm patch](exynos-minigbm.patch) opts the kernel's Exynos DRM driver into minigbm's linear dumb-buffer allocator. Apply it inside the Android `external/minigbm` project. Build the HIDL 4.0 allocator and mapper and `gralloc.minigbm` to rebuild their common `libminigbm_gralloc.so`. The verified 32-bit ARM shared library was used in the isolated Android copy. The existing DRM composer and ANGLE/SwiftShader compositor configuration were retained.

[The kernel networking config](android-netd.config) provides built-in Android networking support, including iptables, netfilter netlink and XFRM. The experiment used the installed Android `netbpfload` and started netd after the BPF completion property was set by the real loader. A Tethering BPF error was still logged on this ARM32 kernel. Service-start and display tests do not establish network functionality.

In the physical boot, SurfaceFlinger registered by 49.457 seconds. Java SystemServer was confirmed at 66.013 seconds. ActivityManager and PackageManager had registered by 81.609 seconds, and WindowManager by 99.308 seconds. All four services were recorded through 288.060 seconds. The software deadline stopped the trial at uptime 300 seconds while ART was still running first-boot package compilation. The Android boot-completed property remained unset in this trial.

[The removable-root helper](../first-stage-trial/removable-system.h) implements the validated first-stage mount. It identifies the removable SD partition, requires the block devices to be read-only, checks the exact file size and ext4 magic, attaches a read-only loop device, and mounts ext4 with journal replay disabled. The tested first-stage init first called `ProtectSystem()`, then `MountRemovableSystem()`, `SwitchRoot("/system")` and `CheckRoot()` with the returned block-device identity. The staged file and DRM-specific Android copy stayed local. The helper's file path and byte count correspond to the verified diagnostic fixture.

The trial used the same board DTB and passed all three complete packed-image replays. Live ACM and three retained-console reads agreed. TWRP returned in software. Full BOOT readback matched `63a79eeb4f9f245277d3e67346af27948aa4da8d72fe72d9c81d8577e1ee8213`. Original RECOVERY matched, and both SYSTEM and EFS retained their payload hashes and reported clean.
