# Android 14 Binder IPC on SM-T700

Trial 25 checks a synchronous Android Binder exchange with the installed `servicemanager` on Linux 6.12.118. The client uses the installed `service` utility in the Android shell domain as UID 2000. Its list request must return the manager's interface descriptor. Separate requests found the registered manager and returned `not found` for a deliberately unregistered name. The latter has the default SELinux service label, for which the policy denied a find operation.

## Build and validation

1. Reuse the previous embedded first-stage init, cgroup files, hardware DTB, installed SELinux policy and read-only MMC guard. Retain the successful bootstrap APEX and linker setup. Package [klimt-binder.rc](klimt-binder.rc) as `/klimt-property.rc` in the embedded ramdisk. The first-stage binary stages it under `/dev`. [Trial 24 setup](../apex-bootstrap-trial/README.md)
2. Replace the previous SELinux entry probe with [binder-entry.h](binder-entry.h), and apply [binder-transaction-log.patch](binder-transaction-log.patch) to the Linux 6.12.118 diagnostic source. Build in Binder IPC, binderfs and the default device names `binder,hwbinder,vndbinder`. Use a fresh matching sixteen-digit hexadecimal run ID in the decompressor records, ramdisk and embedded bootconfig. The tablet command line selects `androidboot.init_rc=/dev/klimt-property.rc`, `androidboot.klimt_binder=1` and `g_serial.iSerialNumber=SMT700-BINDER`.
3. The diagnostic init script mounts binderfs with `stats=global`, creates the stock symlinks, starts the installed manager as UID 1000 and waits for `servicemanager.ready=true`. Its one-shot service retains the manager's stock supplementary groups and cgroup task profile. The shell probe checks the stock client output and publishes a temporary `debug.klimt_binder_probe` property when all three results match. Init records both properties after the shell exits. The prepared kernel can reboot to recovery from an independent workqueue if init stalls.
4. Use [verify-binder-log.py](verify-binder-log.py) with the run ID on both the USB ACM capture and the retained console. The checker verifies enforcing SELinux, the three binderfs nodes in init's mount namespace and the shell's clean exit. It pairs each logged synchronous request and reply by transaction ID, sender and receiver PID, and requires evidence that the driver delivered both to userspace.

For the negative ARM QEMU control, select `androidboot.klimt_binder=0` on the same kernel and installed SYSTEM snapshot. Binderfs mounts and the shell runs the same client. The installed libbinder waits for the readiness property before attempting a Binder exchange. With the manager omitted, the client waits until the independent recovery timeout. The control requires a started shell and zero completed exchanges. Run the console verifier with `--negative`.
