# Linux 6.12.118 early boot and ADB diagnostic for SM-T700

This host-built candidate targets the stock Samsung bootloader and the existing TWRP 3.7.0_9-0. A fifth SM-T700 hardware boot attempt is recorded below. The kernel can save its own banner before userspace, and PID 1 writes another marker before configuring USB. This gives a recovery-side observation when the gadget fails to enumerate. The upstream 6.12 series is maintained as a longterm kernel. [Kernel.org release policy](https://www.kernel.org/category/releases.html)

## Persistent console

The SM-T700 downstream board allocates a 2 MiB persistent console at its configured RAM base plus 512 MiB. Inspection of the installed-version TWRP kernel's decompressed image independently resolved its board descriptor to physical address 0x40000000, size 0x200000 and first descriptor name ram_console. The vendor console's 12-byte DBGC ring header and 16 bytes of Reed–Solomon parity per 128-byte block match the Linux 6.12 ramoops **console** format. The [DT overlay](ram-console.dts) reserves the entire region for this purpose. Registering the pstore console replays previous printk output. Reset or a hang before registration can still leave the previous recovery's log. [Downstream board](https://github.com/retiredcrave/android_kernel_samsung_exynos5420/blob/ece5708530bb80a85b26edeee568733b14740239/arch/arm/mach-exynos/mach-universal5420.c) · [Downstream reader](https://github.com/retiredcrave/android_kernel_samsung_exynos5420/blob/ece5708530bb80a85b26edeee568733b14740239/drivers/staging/android/persistent_ram.c)

## RAM init and image inputs

The [init](init) uses the static ARM BusyBox from Debian bookworm's busybox-static armhf package and the static /sbin/adbd from the verified SM-T700 TWRP ramdisk. It mounts only virtual filesystems. It starts adbd as soon as FunctionFS ep0 exists, waits for the kernel's descriptor-ready attribute, then binds the USB controller under 12000000.usb. Android framework initialization and mounting USERDATA are unnecessary. The daemon uses recovery bionic's property area with ro.adb.secure=1 and ro.secure=1, and accepts the workstation's public ADB key in /adb_keys. The generated image is host-specific and stays private. [TWRP source image](https://dl.twrp.me/klimtwifi/) · [Kernel FunctionFS documentation](https://docs.kernel.org/usb/functionfs.html)

- Start from the [fourth probe](../probe.md#fourth-trial-with-usb-cdc-acm) config and S-BOOT patch. Enable PSTORE, PSTORE_CONSOLE, PSTORE_RAM, USB_CONFIGFS and USB_CONFIGFS_F_FS as built-ins. Disable USB_G_SERIAL and USB_ETH. Set LOCALVERSION to -klimt-early1 and INITRAMFS_SOURCE to the empty string. Run olddefconfig and build the ARM zImage and klimt-wifi DTB. Apply both the single-port overlay and ram-console.dts.
- Build [property-area.c](property-area.c) with the NDK ARMv7 API 21 compiler, linking the extracted recovery libc.so and libdl.so with the /sbin/linker interpreter. Run it as root in a disposable ARM root or QEMU ARM chroot with an empty /dev and LD_LIBRARY_PATH=/sbin. Save its generated /dev/__properties__ as the immutable property-area input.
- Export EARLY_INIT, BUSYBOX_ARM, RECOVERY_ADBD, PROPERTY_AREA and AUTHORIZED_PUBKEY as absolute paths. Supply one authorized Android ADB **public** key. Feed [ramdisk.list](ramdisk.list) to the kernel build's usr/gen_init_cpio with -t 0, then gzip its stdout with gzip -n -9. Use the resulting **external** ramdisk once. Package the zImage appended with the overlaid DTB in a v0 boot container with 2048-byte pages, base 0x10000000, kernel offset 0x8000, tags offset 0x100, ramdisk offset 0x04000000, cmdline `maxcpus=1 rdinit=/init ro loglevel=7`, and append the 16-byte SEANDROIDENFORCE marker. Verify both unpacked payloads and the 8 MiB size limit.

## Observation and verification

1. Before a first trial, save the current recovery console privately as a baseline. After a trial, enter TWRP directly by warm reset if necessary. Capture /proc/last_kmsg immediately with the recovery serial specified, before another reboot. Run `python3 read-console.py previous-console.txt`. An unchanged or empty log leaves the stopping point unknown. On repeats with the same image, use a fresh marker or require a marker-free baseline to distinguish boots.
2. The kernel banner establishes execution at least through printk capture. The PID1 marker establishes execution of the RAM init before gadget setup. Later markers distinguish adbd process launch, FunctionFS descriptor readiness and UDC binding. Binding alone cannot confirm a cable connection. Actual shell success requires the target diagnostic USB serial SMT700-EARLY and a live response to `adb -s SMT700-EARLY shell uname -r`.
3. On the build host the 7,049,232-byte candidate unpacked to the exact staged kernel/DTB and ramdisk. A separate QEMU ARM virt run used the same daemon, properties, shell and init sequence, a disposable key, a dummy UDC and a guest-specific reserved RAM address. The recovered RAM ring contained the banner and all four markers. Its header and 106 populated data blocks passed parity verification. In that run PID 1 marked at 2.59 s, adbd started at 2.73 s, descriptors were ready at 2.94 s and binding completed at 2.98 s. The USB host received a fresh challenge after an untrusted signature. The trusted signature opened a shell that returned the running kernel release and UID 2000. These timings were measured in the emulator.

## SM-T700 hardware trial

On November 19, 2026, TWRP 3.7.0_9-0 captured a marker-free previous console before the first early-ADB trial. The candidate file SHA-256 was `b58e60bf5213272dd7516772de7d1c103536e6640efb0c6e728611758259f826`. After the BOOT write and flush, the complete 8 MiB BOOT read back as `5a46a7c9a3bcb1acd82ba7f601e927e6112c53d1cc813f5037fd1fe1c0666662`, matching the expected image with its preserved partition tail. RECOVERY retained its original hash.

The normal reboot request was issued at 21:47:42 PST. The host saw TWRP disconnect about three seconds into a 185-second capture, followed by 182 seconds with no USB device on the tablet's physical port. No authenticated ADB shell was observed. The USB result cannot establish whether the kernel ran. The diagnostic remained in BOOT at the end of this observation.

TWRP was reachable again at 21:51:45 PST. Its 6,749-byte previous console contained recovery init messages and a recovery reboot. The footer reported 62 corrected bytes and zero unrecoverable blocks. It contained no 6.12.118 release, trial marker or kernel panic line. Both the candidate BOOT and original RECOVERY hashes matched again. The tablet was left in TWRP with the candidate in BOOT. Kernel entry, RAM init and early ADB on SM-T700 remain unconfirmed. The next diagnostic needs an observation earlier than ramoops registration, or a positive control for bootloader handoff.

## Host-tested recovery request and deadline

The November 20 candidate runs Linux `6.12.118-klimt-adbreturn1`. Its RAM init starts USB setup in a child and independently waits for a request from the ADB shell or 120 one-second sleeps, whichever comes first. The deadline also applies to an active ADB session. Before requesting a recovery reboot, PID 1 waits for both Samsung recovery-mode register drivers to bind. Missing bindings leave the guest waiting. A stall before PID 1 starts, or a later kernel lockup, can prevent both ADB and the timer from running. The SM-T700 stayed in TWRP throughout these host tests.

1. Start with the [seventh trial's decompressor and fixed destination](../decompressor/README.md#seventh-trial-with-the-vendor-decompression-address). Keep the external initramfs and the existing USB and console overlays. Set `CONFIG_LOCALVERSION="-klimt-adbreturn1"`, build in `CONFIG_MFD_SYSCON` and `CONFIG_SYSCON_REBOOT_MODE`, and verify `CONFIG_REBOOT_MODE=y` after `olddefconfig`. Apply the [recovery mode overlay](timed-recovery/recovery-mode.dts) to the tablet DTB before appending it to the fixed-address zImage.
2. Build the [ARM restart helper](../decompressor/vendor-control/restart.S) with `armv7a-linux-androideabi21-clang -nostdlib -static -Wl,-e,_start`. Set `EARLY_INIT` to the [timed PID 1](timed-recovery/init), `USB_SETUP_INIT` to the existing [USB setup script](init), and `RESTART_RECOVERY_ARM` to the helper binary. Keep the remaining ramdisk inputs described above. Concatenate the base [ramdisk manifest](ramdisk.list) and the [additional entries](timed-recovery/ramdisk-extra.list) and pass the result to `gen_init_cpio`. Use the same v0 packaging parameters. The verified private candidate measured 7,043,088 bytes against an 8,388,608-byte BOOT partition. Its SHA-256 was `281e835b8b63faf65435d7c35d386ec468b06119b60fc0261f0659b0c61af88a`. Rebuilding with another workstation's public key changes the image.
3. For a hardware trial, identify the diagnostic transport and check `adb -s SMT700-EARLY shell 'uname -r; id -u'`. The expected responses are `6.12.118-klimt-adbreturn1` and `2000`. An authenticated shell can then use `adb -s SMT700-EARLY shell 'touch /tmp/request-recovery'`. Hardware success requires a newly booted TWRP on the physical tablet. Capture its previous console and run the [checkpoint reader](read-console.py) before another reboot.

| ARM emulator test | Observed result |
| --- | --- |
| Authenticated Android SDK ADB over FunctionFS and a dummy USB controller | The shell returned the expected release and UID 2000. PID 1 logged its recovery request at 4.66 seconds of guest uptime. |
| Tablet USB selector with no matching controller | adbd started and FunctionFS became ready. The deadline fired at 125.95 seconds of guest uptime and PID 1 requested recovery. |
| Authenticated request with the INFORM3 driver binding deliberately absent | PID 1 logged that it was waiting. Four seconds later the guest was still running and all bytes of the simulated register bank were unchanged. |

For both reboot cases, the kernel logged `Restarting system with command 'recovery'`. A before-and-after read of the 4 KiB simulated register bank showed the expected INFORM2 value `0x12345678` at offset `0x808` and INFORM3 value `0x12345674` at `0x80c`. All other bytes matched. The emulator used a disposable ADB key, a guest USB transport relay for the authenticated cases, and a RAM-backed syscon. The physical Exynos USB controller, PMU reset and S-BOOT selection of TWRP still require a hardware trial. The earlier [vendor-kernel controls](../decompressor/README.md#eighth-trial-with-the-vendor-34-decompressor) reached TWRP from running vendor userspace.
